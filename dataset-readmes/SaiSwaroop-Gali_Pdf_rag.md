# Multi Model Hybrid Graph RAG for Research Paper Question Answering

## Overview

Large Language Models (LLMs) often struggle to answer domain-specific questions accurately when relying solely on their pre-trained knowledge. While traditional Retrieval-Augmented Generation (RAG) systems improve factual accuracy through semantic retrieval, they typically lack the ability to reason over structured relationships contained within technical documents.

This project presents a **Hybrid Graph Retrieval-Augmented Generation (Hybrid Graph RAG)** pipeline that combines **vector similarity search** with **knowledge graph retrieval** to improve question answering over AI research papers.

The system extracts **text, tables, and images** from research papers, constructs both a **semantic vector index** and a **Neo4j knowledge graph**, and fuses the retrieved context to generate grounded responses.

Beyond the core RAG pipeline, the project introduces **telemetry logging**, an **automated benchmark evaluation harness**, a **Grounding Agent** for answer verification, and an **LLM-based Web Agent** that extends the system beyond the local knowledge base when sufficient evidence cannot be found.

# Project Workflow

The complete pipeline consists of the following stages:

1. Parse research papers in PDF format.
2. Extract text, tables, and images.
3. Perform semantic chunking using an LLM.
4. Generate semantic embeddings.
5. Store document chunks in ChromaDB.
6. Extract entities and relationships from the documents.
7. Construct a Neo4j Knowledge Graph.
8. Perform Hybrid Retrieval (Vector + Graph).
9. Fuse graph and vector contexts.
10. Generate an answer using the retrieved evidence.
11. Record retrieval telemetry for analysis.
12. Evaluate the system using an automated benchmark harness.
13. Verify the generated answer using the Grounding Agent.
14. If the answer cannot be grounded or sufficient local evidence is unavailable, route the query to the Web Agent.
15. Return the final response.

# Pipeline Components

## 1. Multimodal Document Processing

The pipeline extracts multiple information modalities from research papers:

- Text
- Tables
- Figures / Images

This enables the retrieval system to leverage information beyond plain document text.

---

## 2. Semantic Chunking

Instead of fixed-size chunking, the project uses an LLM to perform semantic chunking, preserving logical document structure and improving retrieval quality.

---

## 3. Vector Retrieval

Each semantic chunk is embedded using OpenAI embeddings and stored in ChromaDB for dense semantic retrieval.

---

## 4. Knowledge Graph Retrieval

Entities and relationships are extracted from the research papers and stored inside Neo4j.

Graph retrieval enables structured reasoning across connected concepts that traditional vector search alone may overlook.

---

## 5. Context Fusion

The retrieved graph context and vector context are merged into a single prompt supplied to the answering model.

This hybrid approach combines semantic similarity with explicit relationships extracted from the documents.

---

## 6. Grounding Agent

Before returning an answer, a dedicated Grounding Agent verifies whether every significant claim is supported by the retrieved evidence.

Possible outputs:

- **GROUNDED**
- **NOT_GROUNDED**

This additional verification step reduces unsupported or hallucinated responses.

---

## 7. Web Agent

If the Grounding Agent determines that the local knowledge base does not sufficiently support the generated answer, the query is routed to an LLM-based Web Agent.

The Web Agent enables the system to answer questions outside the indexed research papers instead of simply rejecting them.

# Telemetry & Evaluation

One objective of this project was not only to build a Hybrid Graph RAG system, but also to understand **how well it performs**.

To achieve this, the notebook includes an observability and evaluation layer.

---

## Telemetry Logging

For every benchmark query, the pipeline records retrieval statistics including:

- User question
- Retrieved graph entities
- Retrieved graph triples
- Vector retrieval results
- Generated answer
- Final retrieval outcome

These telemetry logs provide insight into retrieval behavior and help identify failure cases.

---

## Benchmark Evaluation Harness

An automated benchmark harness was developed to evaluate the complete Hybrid Graph RAG pipeline.

The benchmark consists of:

- In-domain research questions
- Out-of-domain knowledge questions

The harness automatically executes each benchmark query through the pipeline and records the generated responses.

Example benchmark questions include:

- How does Reflexion use episodic memory?
- What are the components of the Reflexion framework?
- How does SELF-RAG use reflection tokens?
- How does AutoGen implement conversation programming?
- How does SkillOpt perform bounded skill updates?
- How does Ragas evaluate faithfulness?
- Who painted The Starry Night?
- What is the standard boiling point of water?
- How many bones are there in an adult human body?

---

## Failure Analysis

Telemetry collected during benchmark evaluation enables analysis of retrieval failures, including:

- Missing graph entities
- Sparse graph relationships
- Low-quality retrieval
- Unsupported questions
- Out-of-domain queries

These observations motivated the addition of the Grounding Agent and Web Agent.

# Neo4j Setup

The knowledge graph is hosted using Neo4j running inside Docker.

Start a Neo4j container:

```bash
docker run \
  --name neo4j \
  -p 7474:7474 \
  -p 7687:7687 \
  -d \
  -e NEO4J_AUTH=neo4j/password \
  neo4j:latest
```

After startup:

Neo4j Browser:

```
http://localhost:7474
```

Bolt Endpoint:

```
bolt://localhost:7687
```

# Motivation

This project was developed to explore how semantic retrieval and structured knowledge graphs can be combined to improve Retrieval-Augmented Generation systems for technical literature.

Rather than stopping at a working Hybrid Graph RAG pipeline, the project incrementally introduces telemetry, benchmark evaluation, failure analysis, grounding verification, and an LLM-based Web Agent to improve robustness and extend the system beyond its indexed documents.

The resulting architecture demonstrates a complete end-to-end RAG workflow that emphasizes both retrieval quality and answer reliability while providing a practical framework for evaluating and improving research-oriented question answering systems.
