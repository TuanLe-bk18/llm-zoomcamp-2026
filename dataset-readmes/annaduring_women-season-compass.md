# Perimenopause Symptom Assistant

A RAG-powered Q&A assistant, grounded in vetted medical and coaching sources, that answers perimenopause questions with citations, lets users one-tap (or free-text) log symptoms, and surfaces a personalized daily tip with a source.

## Problem

**Problem:** Perimenopause information is scattered across medical sites, forums, and blogs of wildly varying quality; women often can't tell reliable guidance from noise, and generic search doesn't surface citation-backed answers.

**Who it's for:** Women in perimenopause looking for grounded answers and simple day-to-day symptom awareness — not a diagnostic tool, not a replacement for a clinician.

**What "done" looks like:** Ask a question, get an answer grounded in a real source with a citation; tap (or type) to log a symptom; see a relevant, cited tip.

## Architecture

```
women-season-compass/
├── data/                  # content: source snapshot, tip bank, ground truth, eval results
├── src/
│   ├── core/              # shared config, cached clients (Anthropic, ES, Postgres, embedding model)
│   ├── ingest/             # scrape -> chunk -> build_index
│   ├── rag/                 # hybrid retrieval, prompts, generation
│   ├── eval/                 # ground truth generation, retrieval eval, LLM-as-judge eval
│   └── app/                   # Streamlit app + Postgres logging
├── monitoring/             # Postgres schema, Grafana provisioning + dashboard
├── docker-compose.yml       # elasticsearch, postgres, grafana, app
└── Dockerfile                # app image
```

Question → hybrid retrieval (Elasticsearch: BM25 + dense vector, fused via RRF) → Claude generates a cited answer → logged to Postgres → visualized in Grafana.

## Data & knowledge base

- **26 source pages and indexed** curated across 5 authoritative sites: The Menopause Society, NHS, ACOG, Cleveland Clinic.
- Cleaned page text is committed to `data/sources/` as a snapshot, so rebuilding the index never depends on re-scraping live sites.
- **27-entry tip bank** (`data/tip_bank.json`): `text`, `source_name`, `source_type` (`clinical`/`coaching`), `symptom_tags` — clinical tips paraphrased from the same source set, plus a generically-framed coaching-style subset (not attributed to a specific named brand, since that wasn't confirmed).
- **152 chunks** indexed from the 21 pages (~300-500 tokens each, with overlap — see Design decisions).
- **76-pair ground truth Q&A set** (`data/ground_truth.json`), generated by prompting Claude with each chunk to produce a question it answers, then manually reviewed and pruned (dropped questions generated from boilerplate like a "find a doctor" CTA or an author bio; split one compound two-part question into two).

## Retrieval flow

Elasticsearch serves as a single hybrid BM25 + dense-vector engine — one dependency instead of a separate vector DB alongside a keyword index. Dense vectors come from a local `sentence-transformers` model (no external embeddings API needed, since Claude has none). BM25 and dense (kNN) results are fused with Reciprocal Rank Fusion, computed in Python (`src/rag/retrieval.py`) rather than via Elasticsearch's built-in `rank.rrf`, which is gated behind a higher license tier than this project's basic-license single-node setup.

### Retrieval evaluation

Compared BM25-only vs. hybrid (BM25 + dense via RRF) against the 76-pair ground truth set, at k=5:

| approach | hit-rate@5 | MRR@5 |
|---|---|---|
| BM25-only | 0.539 | 0.370 |
| **hybrid** | **0.658** | **0.505** |

**Kept: hybrid.** It wins clearly on both metrics. This matches the expected mechanism for this domain: perimenopause questions mix exact clinical terminology ("vasomotor symptoms") that BM25 catches, with paraphrased lay-language questions ("why am I so hot at night") that dense retrieval catches — neither approach alone covers both query styles well.

### LLM evaluation

Compared two prompt variants — a plain instruction prompt vs. one with explicit "cite only from context, say you don't know otherwise" guardrails (strict) — over 20 sampled ground-truth questions, judged by Claude on groundedness, relevance, and citation presence:

| variant | groundedness | relevance | citation_rate |
|---|---|---|---|
| plain | 4.95 | 5.00 | 30.0% |
| **strict** | 4.95 | 4.95 | **100.0%** |

**Kept: strict.** Groundedness and relevance are similar but citation presence is decisive: strict cited a source 100% of the time. Given the nature of requests, citations are preferred and 'strict' is the only variant that actually satisfies the requirements.

## Design decisions

These are deliberate engineering trade-offs, not defaults left unexamined:

- **Chunk size (~300-500 tokens, ~50-word overlap):** balances citation precision against context loss. Smaller chunks would fragment multi-sentence clinical explanations (e.g., a symptom's cause + treatment split across chunks); much larger chunks would dilute retrieval precision and bloat the context window with irrelevant surrounding text, given how dense and topic-mixed some source pages are (see MenoNotes note below).
- **Embedding model (`BAAI/bge-small-en-v1.5`):** chosen over an OpenAI embedding model specifically because the generation LLM is Anthropic Claude, which has no embeddings API. the local model runs entirely on CPU at this corpus size, with zero additional API cost.
- **Retrieval strategy (hybrid over BM25-only or dense-only):** validated empirically above, not assumed — hybrid's 22-point hit-rate improvement and 36% MRR improvement over BM25-only directly reflects the mixed exact-terminology/lay-language nature of real perimenopause questions.
- **Prompt variant (strict over plain):** validated empirically above — citation presence, not just answer quality, is a hard product requirement here, and only the strict guardrail prompt reliably delivers it.

## Interface

A single Streamlit app (`src/app/streamlit_app.py`):
- **Chat panel** — ask a question, get a cited answer, thumbs up/down feedback.
- **Symptom logger** — one-tap buttons for common symptoms, plus free-text entry for anything not in the preset list, both writing to the same `symptom_logs` table. A personal trend chart shows the user's own logged symptoms over time.
- **Tip card** — pulled from the tip bank, biased toward tags matching recently logged symptoms, with a "show another tip" button.

## Monitoring

Every query, feedback vote, symptom log, and tip interaction is logged to Postgres (`monitoring/init_db.sql`: `query_logs`, `feedback`, `symptom_logs`, `tip_engagement`). A provisioned Grafana dashboard (`monitoring/grafana/dashboards/perimenopause_dashboard.json`) has 6 panels:

1. Queries per day
2. Thumbs up/down rate over time
3. Retrieval latency over time
4. Most-logged symptoms (bar chart)
5. Most common question topics — derived from the top retrieved chunk's source-page topic
6. Tip-card "show another" taps

## Known limitations

- The corpus is based off of online articles, that present a watered version of scientifc peer-reviewed articles.

## Reproducibility

- `.env.example` lists every required variable name with no values
- Dependencies are pinned via `uv` (`pyproject.toml` + `uv.lock`).
- The scraped, cleaned source snapshot (`data/sources/`), tip bank, ground truth set, and eval results are all committed — rebuilding the index or re-running evaluation never depends on live scraping or re-generating ground truth.

### Setup

1. Clone the repo and `cd` into it.
2. Copy `.env.example` to `.env` and fill in real values (an Anthropic API key, and Postgres/Grafana credentials of your choice).
3. `docker-compose up -d --build` — brings up Elasticsearch, Postgres, Grafana, and the Streamlit app (built from `Dockerfile`).
4. Build the search index (one-time, or whenever `data/sources/` changes):
   ```bash
   uv sync
   uv run python -m src.ingest.build_index
   ```
5. Open the app at `http://localhost:8501` and Grafana at `http://localhost:3000` (log in with the `GRAFANA_ADMIN_USER`/`GRAFANA_ADMIN_PASSWORD` you set in `.env`).

To re-run the evaluation pipeline yourself:
```bash
uv run python -m src.ingest.scrape              # re-scrape (optional, snapshot already committed)
uv run python -m src.eval.generate_ground_truth  # regenerate ground truth Q&A
uv run python -m src.eval.eval_retrieval         # BM25 vs hybrid comparison
uv run python -m src.eval.eval_llm               # prompt variant comparison
```
